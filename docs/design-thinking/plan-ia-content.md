## Steps (each saved in `docs/design-thinking/`, one review with Dani at the end)
1. **Full service inventory v2** → update `content-inventory.md`: every service from the price sheet, pricing.md, business.md and the blog; for each: "from £" (or TBC), search demand, proof available (photos), persona, tier (menu / hub + footer / contextual / drop).
2. **User tasks and entry points** → `user-journeys.md`: top tasks per persona (e.g. "my keyless car could be stolen, what do I fit?", "how much to wrap my car?", "CarPlay for my 2016 Mini"), where they arrive from, and the shortest path to "Contact us".
3. **Labels and grouping check** → update `card-sort.md`: test Protect/Upgrade/Style against plain labels with the inventory and search terms; recommend one.
4. **Keyword map** → `keyword-map.md`: one primary + 2–3 secondary terms per page (from Search Console + `seo.md`), no two pages chasing the same term; decide local/area pages.
5. **Site map v2 + IA** (with the `information-architecture` skill) → rewrite `sitemap.md`: full page list, tiers, URLs, menu, footer, breadcrumbs, internal links, redirects, and the "hubs only in footer" rule.
6. **Content model per page type** → `content-model.md`: Home, hub, service, car-specific, Builds, build detail, blog, About, Contact, Prices (if yes): purpose, the one question it answers, blocks in order, proof, FAQ source, primary action, SEO fields (title / description / schema).
7. **Content plan + gaps for Hypa** → `content-plan.md`: who writes what, which facts Hypa must confirm, photos needed per page, priority order for launch.
8. **One artifact to review it all**: site map diagram + tables, so you and Hypa can comment before any copy is written.

Then: rewrite the key pages from the content model (copy in Hypa's voice, facts confirmed), and continue the Drive media review in parallel.
